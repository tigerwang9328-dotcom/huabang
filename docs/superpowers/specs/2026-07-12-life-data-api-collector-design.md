# 生意经油猴 API 采集与 AI 中台接入设计

## 目标与边界

第一阶段只覆盖抖音来客已绑定主体“贵阳市雅斯贸易有限公司”（`groupid=1798826701211732`）。油猴在已登录的 `life-data.cn` 页面内主动调用生意经内部 API，Cookie 由浏览器自动携带且永不上传。油猴只把业务请求参数和业务 JSON 响应传给华邦 AI 中台。

核心结果指标是实际核销金额。自然播放首次达到或超过 2,000 的视频立即生成 AI 中台草稿待办，仍由人工判断是否投放。生意经视频数据当前最大日期为昨日，因此“立即”是指平台数据更新且采集页面在线后立即发现，不承诺分钟级实时。

## 采集架构

### 油猴脚本

- 在 `document-start`、页面加载完成及 SPA 路由变化后安装 XHR/fetch 监听，只处理 `life-data.cn/api` 的业务接口。
- 从页面真实请求学习 `x-tt-ls-session-id`、`root-life-account-id`、`life-account-id` 和成功请求模板；不读取或上传 Cookie、Authorization、站内消息与风控日志。
- 主动调用视频分析 `POST /api/dito/query`，path 为 `/flow/content/analysis/video`。视频列表每批 `limit=100`（已实测成功），按 `offset` 自动取完全部数据。
- 视频每 5 分钟轮询；其他经营、流量、商品、人群、直播等接口在用户访问时被动采集，并保存最后一个成功模板用于每 30 分钟重放。
- 使用 `GM_xmlhttpRequest` 批量上传，`GM_setValue` 保存失败队列；指数退避重试，队列恢复后按原采集时间补传。
- 页面浮层显示账号、最近采集时间、上传状态、队列数和“立即采集”按钮；同一浏览器多标签只允许一个主标签运行定时任务。

### AI 中台

- 新增只写接口 `POST /api/v1/life-data/ingest`，使用独立、可撤销、仅限该主体的采集令牌；令牌在服务端只保存哈希。
- 入参包含 `schema_version`、`event_id`、主体、页面/API、请求参数、业务响应及采集时间。服务端限制来源账号、接口白名单、单次大小和请求频率。
- 原始业务 JSON 留档，同时解析视频快照。每条视频以 `item_id` 唯一识别，保存作者、标题、发布时间、播放、5 秒率、完播率、观看时长、互动、进店、直接/间接成交、核销、退款、券数和千次播放成交金额。
- 相同 `event_id` 幂等；视频指标无变化时不重复新增快照。原始采集保留 90 天，标准化快照长期保留。
- 采集状态记录最近在线、最后成功、队列补传和解析错误；连续失败只改变状态，不写入伪造的零值数据。

## 阈值提醒与后续分析

- 规则固定为 `natural_play_2000`。首次导入时已达到 2,000 的视频也生成一次“首次导入已过线”事件；以后仅在上次小于 2,000、本次达到或超过 2,000 时触发。
- 事件表对“主体 + item_id + 规则”做唯一约束，再创建 `AppActionTask` 草稿，避免重传、补传和并发导致重复待办。
- 待办证据包含视频、作者、播放量及增量、5 秒率、完播率、互动、成交、核销、退款和统计周期；建议动作仅为“小额测试投放并人工确认”，不自动花费。
- 数据积累后按视频、作者、素材特征、商品、区域和时段计算与实际核销金额的相关关系和滞后关系；相关性不表述为因果，投放建议以核销投产比为最终排序口径。

## 安全、错误与验收

- 上传内容严禁包含 Cookie、请求头、Authorization、站内消息和平台风控日志；日志对令牌和业务正文做脱敏。
- 登录失效、账号不匹配、API 返回非成功码、结构变化或上传失败时，浮层明确显示错误；恢复登录后自动继续并补传本地队列。
- 后端测试覆盖令牌鉴权、账号限制、请求大小、幂等、解析、金额分转元、无变化去重、2,000 阈值恰好一次和并发重复。
- 油猴测试覆盖请求模板学习、100 条分页、114 条完整补采、过滤敏感接口、多标签主节点、离线队列及恢复重传。
- 线上验收：114 条视频全部入库；34,310 播放视频被识别且只产生一次待办；重复采集不重复提醒；后台数据库与日志中不存在 Cookie。
