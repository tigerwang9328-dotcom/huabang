# 费用缺失时展示估算经营利润设计

## 背景与目标

经营总览当前在费用不完整时将经营利润隐藏为“待接入”。新口径要求：费用缺失时仍展示一个可追溯的估算值，同时明确标注估算状态、已扣费用、费用覆盖率和具体缺失费用；不得把估算值包装成财务核准利润。

## 已确认口径

- 采用方案 A：`估算经营利润 = 毛利额 - 当前已接入费用`。
- 未接入费用不做历史均值填充，也不虚构预算值；计算时暂按 0 处理。
- 只要毛利额可计算，即可输出估算经营利润；毛利本身为估算时，经营利润继续标记为估算，并同时说明成本覆盖情况。
- 费用八类全部覆盖且全部财务核准后，状态从 `estimated` 自动升级为 `ready`，名称显示“经营利润”。
- 毛利额不可计算时，经营利润仍为 `pending_data`，不制造估算值。
- 经营利润率仅在销售额大于 0 时计算。

费用必备类别保持现有八类：租金、工资、社保、平台费、水电、物流、营销、其他。

## 数据与状态

后端继续使用现有 `calculate_profit` 作为唯一利润计算入口：

- `operating_profit`：费用完整时为核准值，费用不完整时为按已接费用扣减后的估算值。
- `operating_profit_status`：完整核准为 `ready`；费用覆盖不全、费用未核准或毛利为估算时为 `estimated`；毛利不可计算时为 `pending_data`。
- `expense_coverage_rate`：已声明的“费用类别天数 / 八类必备费用类别天数”。
- `missing_expense_types`：返回所有缺失类别代码。
- `total_expense`：只汇总当前已经接入且落入查询期间的费用。
- `reasons`：继续保留 `cost_incomplete`、`expense_coverage_incomplete`、`finance_not_approved` 等机器可读原因。

现有数据库字段足以承载本次调整，不新增迁移。DWS、DM、经营快照、经营日报和财务分析统一读取同一计算结果，避免页面各自重算。

## API 与页面展示

现有接口地址和字段保持不变，属于非破坏性语义扩展：

- 经营总览 `/dashboard/overview` 的 `command_center.metrics.operating_profit` 返回估算值、`estimated` 状态、来源、覆盖率说明和缺失费用中文名称。
- 经营日报 `/report/boss-daily/{date}` 同步返回估算经营利润和缺失原因。
- 财务利润分析保留 `expense_coverage_rate`、`missing_expense_types` 和费用分项，状态文案改为“估算，待补齐并核准费用”。
- 经营总览核心指标新增“估算经营利润”卡片；核准完成后自动显示“经营利润”。
- 卡片说明示例：`估算 · 已扣费用 ¥0 · 覆盖率 0% · 缺失：租金、工资、社保、平台费、水电、物流、营销、其他`。
- 说明过长时允许换行或通过提示浮层完整展示，不能只显示“估算”而隐藏缺失项。

## AI 与规则边界

- AI、异常规则和老板结论不得依据 `estimated` 状态输出“公司已盈利”或“公司已亏损”的确定性判断。
- 估算值可作为事实卡片展示，也可在 AI 限制说明中引用，但必须同时带出缺失费用和覆盖率。
- 只有 `operating_profit_status=ready` 且财务核准完成时，利润类规则才能触发确定性盈亏结论。
- 大模型不可用时继续使用确定性模板，不影响估算值生成。

## 测试与验收

1. 八类费用完整且均已核准：经营利润为核准值，状态 `ready`，缺失列表为空。
2. 缺少一类费用：经营利润等于毛利减已接费用，状态 `estimated`，缺失列表准确。
3. 八类费用全部缺失：估算经营利润等于毛利，状态 `estimated`，覆盖率 0%，列出八类缺失项。
4. 有费用但尚未核准：已扣除该费用，状态仍为 `estimated`，说明“待财务核准”。
5. 毛利成本不完整：如果毛利额可计算则继续展示双重估算并注明成本与费用缺失；毛利额不可计算则经营利润保持 `pending_data`。
6. AI 和利润异常规则不对 `estimated` 值输出确定性盈亏结论。
7. 经营总览、经营日报、财务利润页同日数值、状态、覆盖率和缺失项一致。
8. 重算现有经营快照，不重新调用百胜接口；执行后端全量测试、前端测试、类型检查、生产构建和桌面/移动端截图检查。
