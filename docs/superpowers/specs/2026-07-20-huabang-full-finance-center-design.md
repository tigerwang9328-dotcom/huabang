# 华邦完整财务中心设计

## 1. 目标

在华邦 AI 中台复现牧马人财务中心已经落地的会计核算与业务管理能力，并以华邦现有三套金蝶 K/3 WISE 历史账为正式期初。华邦成为独立可写的记账系统，金蝶仅作为不可篡改的历史来源，不进行任何回写。

首期交付完整财务中心：账套、科目、凭证、总账、明细账、科目余额、三大报表、应收应付、出纳、银行对账、固定资产、发票、工资、税务、自动凭证、期末处理、财务罗盘、辅助核算、报表映射和操作日志。

## 2. 已确认决策

- 三个正式金蝶账套继续作为三个独立法人账套，不合并。
- 采用双层账本：金蝶来源证据层永久只读，华邦正式账本可写。
- 历史凭证导入正式账本后为已过账，历史期间为已结账。
- 修改历史凭证必须依次反结账、反过账、修改、审核、重新过账、重新结账。
- 财务角色拥有完整财务操作权限；老板只读，非财务角色不可访问敏感财务数据。
- 百胜、钉钉和其他业务来源只生成凭证草稿，人工审核过账后才影响总账。
- 报表按金蝶科目编码和会计准则自动预映射；未确认映射时不得生成正式三表。
- 各账套按自己的金蝶截止期连续接账，缺失期间补齐并对账后才开放后续期间。
- 不覆盖现有 `dwd_finance_expense`、`dwd_finance_cash`，不改变百胜销售、库存、会员和采购事实。

## 3. 架构

### 3.1 来源证据层

继续使用现有 `ods.kingdee_*`、`dwd.dwd_gl_*`、原始 `.bak`、canonical manifest 和导入批次。该层禁止业务修改，用于：

- 展示金蝶原始快照。
- 校验华邦正式账本的首次迁移。
- 追踪 `source_system`、`source_database`、`source_pk`、`import_batch_id` 和文件哈希。
- 在争议、审计或恢复时提供原始证据。

### 3.2 正式记账层

新增 `fin` schema，使用独立模型，避免把可写状态混入 ODS/DWD：

- `fin.book`：账套、法人、本位币、会计准则、启用和当前期间。
- `fin.period`：期间状态 `open/closed/locked`、结账与反结账记录。
- `fin.account`：科目层级、类型、余额方向、数量/外币/现金流属性。
- `fin.aux_category`、`fin.aux_item`：客户、供应商、部门、员工、项目、门店等辅助核算。
- `fin.voucher`、`fin.voucher_entry`：凭证头和分录，支持草稿、审核、过账、反过账和红冲。
- `fin.voucher_version`：每次变更前后的完整 JSON 快照、操作者和原因。
- `fin.ledger_balance`：账套、科目、期间粒度的正式余额。
- `fin.statement_mapping`、`fin.statement_line`：三表模板和科目映射。
- `fin.operation_log`：财务操作审计。
- `fin.source_link`：正式记录与金蝶、百胜、钉钉来源记录的多对多追踪。

业务模块表按边界拆分：`fin.receivable`、`fin.payable`、`fin.settlement`、`fin.cash_account`、`fin.bank_transaction`、`fin.reconciliation`、`fin.fixed_asset`、`fin.depreciation`、`fin.invoice`、`fin.payroll`、`fin.tax_record`、`fin.auto_entry_rule`、`fin.auto_entry_run`。

### 3.3 报表与分析层

总账、明细账、余额表和法定报表仅使用已过账凭证及正式余额。经营罗盘可以组合百胜经营指标，但必须将“法定会计结果”和“经营估算”分栏展示并标明来源。

## 4. 凭证状态机

状态为 `draft -> reviewed -> posted -> reversed`：

- 草稿允许修改和删除，不影响总账。
- 审核要求借贷平衡、科目有效、辅助核算完整、期间开放。
- 过账在单一数据库事务中写入余额并生成审计日志。
- 已过账凭证不能直接编辑或删除；必须反过账。
- 已结账期间不能反过账；必须先反结账。
- 红冲生成方向相反、金额相同的新凭证，并关联原凭证。
- 每次保存、审核、过账、反过账、红冲和删除均写入版本与操作日志。
- 金蝶导入凭证保存 `origin_kind=kingdee_history`；来源快照不可修改。

财务角色可以执行全部操作，但危险操作必须填写原因并二次确认。老板只能查询、导出和穿透。

## 5. 历史数据迁移

1. 从已验证的 DWD/ODS 复制三个账套、416 个科目、339 张凭证、4,596 条分录和 6,868 条余额到 `fin`。
2. 保留金蝶原始主键和导入批次；正式账本生成独立主键。
3. 历史凭证初始为 `posted`，来源状态单独保存，不伪造金蝶状态。
4. 金蝶已覆盖期间初始化为 `closed`；没有凭证但有余额的期间同样保留。
5. 首次迁移必须校验逐账套行数、借贷平衡、头分录合计和余额方程。
6. 重复迁移使用 `book_id + source_system + source_database + source_pk` 唯一键，行数和金额不得变化。
7. 金蝶截止期后的缺口进入 `pending_gap`，在补采完成前禁止结账和生成正式报表。
8. 补采数据先进入导入批次和草稿，人工确认后过账。

## 6. 报表映射

- 根据金蝶科目编码、科目类型和余额方向生成预映射。
- 资产负债表、利润表和现金流量表分别维护映射状态。
- 映射状态为 `suggested/confirmed/rejected`。
- 任一有余额或发生额的科目未确认映射时，对应报表状态为 `pending_mapping`。
- 缺期间数据时状态为 `pending_data`；存在账期断档时为 `pending_gap`。
- 只有全部检查通过时状态为 `ready`，才允许标记正式和导出。
- 报表金额可穿透到科目余额、明细账、凭证和来源快照。

## 7. 完整财务中心页面

- 财务首页：资金、往来、收入费用、待办、数据质量和期间状态。
- 凭证管理：录凭证、查凭证、凭证汇总、模板、自动凭证草稿。
- 账簿查询：总账、科目余额表、明细账。
- 财务报表：资产负债表、利润表、现金流量表、费用、税金、应收、应付明细。
- 往来管理：应收单、应付单、收付款核销、账龄分析。
- 出纳管理：现金银行账户、资金流水、银行对账、余额调节表。
- 专项管理：固定资产、折旧、发票、工资、税务。
- 期末处理：试算平衡、损益结转、结账、反结账。
- 基础设置：账套、科目、辅助核算、报表映射、自动凭证规则、操作日志。

现有 `/app/fin/history/*` 保留兼容并重定向到新页面。界面遵循华邦现有设计系统，不复制牧马人的品牌和专属文案。

## 8. 自动凭证

- 百胜销售、退货、采购入库只产生建议分录和草稿。
- 钉钉报销、付款、工资审批只产生草稿，并保留审批单号和附件。
- 自动规则必须绑定账套、业务类型、科目、税率、辅助核算和生效期间。
- 同一来源单据只能生成一次有效草稿；重新生成必须作废旧草稿并记录原因。
- 自动凭证不得自动审核或自动过账。
- 缺科目、组织映射、金额或附件时进入异常队列，不静默跳过。

## 9. API 与权限

新增 `/api/v1/finance` 下的账套、期间、科目、凭证、账簿、报表、往来、出纳、资产、发票、工资、税务、自动凭证、结账、映射和审计接口。

权限拆分为查询、制单、审核过账、反操作、结账、配置和导出。按用户决策，财务角色授予全部财务权限；老板授予只读和导出；其他角色默认无权限。凭证摘要、往来单位、工资、税务和资金字段继续受财务权限保护。

## 10. 错误处理与并发

- 过账、反过账、结账和反结账使用数据库事务和账套期间级锁。
- 使用凭证版本号做乐观并发控制，过期版本返回冲突而不是覆盖。
- 状态不合法、期间关闭、借贷不平衡、映射缺失和来源重复均返回明确错误码。
- 所有批量任务记录总数、成功数、失败数、错误详情和可重试状态。
- 任何失败不得留下半张凭证或部分余额更新。

## 12. 非目标

- 不回写或控制金蝶服务器。
- 不复制牧马人聚水潭、广告费、平台店铺和硬编码科目模板。
- 不自动审核或自动过账业务来源数据。
- 不在映射、账期或数据缺口未完成时生成伪正式报表。
