# 独立财务中心应收应付台账设计

## 目标

将“应收应付”由一个混合页面完善为应收单台账、应付单台账、账龄分析三个入口；继续使用华邦独立财务中心的现有持久化 API 和人工审核、人工结算状态机。

## 边界

- 牧马人 `D:\tanliniu\mumaren_finance` 只作为页面划分和账龄分桶的只读参考。
- 不调用旧财务 API、不使用旧 `fin_*` 表，也不改写金蝶来源。
- 单据录入保持单号、日期、往来单位、总金额、备注；本次不增加商品明细、税率或库存映射。
- 当前账簿允许草稿、审核、人工结算、删除草稿；金蝶迁移账簿永久查询只读。

## 页面与数据流

| 入口 | 数据 | 允许操作 |
| --- | --- | --- |
| 应收单台账 | `order_type=receivable` 的独立 AR/AP 订单 | 当前账簿录草稿、审核、人工结算、删除草稿 |
| 应付单台账 | `order_type=payable` 的独立 AR/AP 订单 | 当前账簿录草稿、审核、人工结算、删除草稿 |
| 账龄分析 | 同一账簿的应收或应付未结余额 | 查询、按账龄和往来单位查看 |

三个页面都使用 Pinia 中的 `mumaren-finance-center:selected-book-id`，账簿切换后重新请求对应 `book_id` 数据。金蝶迁移账簿的页面按钮、对话框入口及行内动作禁用，后端与数据库仍是最终拒绝层。

## 验收

1. 侧边栏“应收应付”下出现并路由到三个独立入口。
2. 应收与应付台账不混淆，并显示未结余额、审核状态、结算状态。
3. 账龄页可分别查询应收和应付，展示 0–30、31–60、61–90、91–120、120+ 天及往来单位余额。
4. 历史账簿在三页均不可写；普通账簿原有流程仍可用。
5. 前端测试、类型检查、构建、相关后端测试和浏览器验收通过。
