# 华邦财务中心 V2.1 设计

## 目标与范围

在华邦 AI 中台内重建一个可独立演进的财务中心，而非把既有拆分页和服务拼装到新菜单。入口固定为“财务利润 → 财务中心”；既有财务首页、利润分析、报销、付款、费用分析、正式账簿与历史财务入口全部保留兼容。

本次交付覆盖账套、科目、辅助核算、凭证、总账、明细账、余额、法定报表、应收应付、出纳对账、资产、发票、工资、税务、自动草稿、期间结账、财务驾驶舱、设置和审计。任何页面必须接入真实查询或受控写入，不能以静态占位冒充可用。

## 核心架构

财务中心采用四层边界：

1. **来源证据层**：金蝶 ODS/DWD 快照保持不可写；百胜、钉钉和华邦业务事实表保持各自所有权。
2. **历史账层**：金蝶记录导入新的 `fin` schema，带不可移除的历史标记和来源链路，用于查询、穿透和与当前账隔离展示。
3. **当前记账层**：当前华邦业务经适配器形成草稿；草稿经审核和人工过账后才影响正式余额与报表。
4. **应用层**：`/api/v1/finance-center` 是新模块唯一后端契约；前端配置集中于 `frontend/src/config/financeCenterModules.ts`，页面不直接依赖旧拆分服务。

新模块可以读取现有经营数据，但不得重写 `dwd_finance_expense`、`dwd_finance_cash`、百胜事实或钉钉事实。所有金额使用十进制精度，禁止浮点入账。

## 历史金蝶数据写入与标记

金蝶数据会写入新的财务模块，但绝不伪装成华邦当期账。每条导入的账套、科目、期间、凭证、分录、余额与来源链接均保存：

- `is_historical=true`；
- `origin_kind=kingdee_history`；
- `source_system=kingdee`、来源账套/数据库、来源主键、导入批次、原始哈希；
- 导入时间、导入执行人、校验结果和可追溯的导入批次。

历史记录默认只读；不能被当前的编辑、审核、人工过账、自动草稿或当前期间结账流程修改。前端在列表、详情、凭证、账簿和报表穿透处显示“历史数据”标记。报表筛选必须明确区分“仅当前华邦账”“仅历史账”“含历史数据”；默认仅当前华邦账，防止无意混算。

导入必须幂等：同一来源键和内容哈希再次运行不会产生重复数据；内容冲突产生阻断性差异报告，而非覆盖原记录。历史数据写入前后分别核对账套、科目、凭证、分录、余额、借贷合计和来源链接；任何差异阻止发布。

## 会计状态与权限

所有当前业务写入统一使用：`draft → reviewed → posted`。冲销生成关联的新凭证；已过账凭证不能直接编辑或删除；已结账期间必须先按权限反结账才能进行允许的反操作。历史导入的记录不参加这条写入状态机。

每次保存、审核、过账、冲销、导入、结账、反结账、规则执行和配置修改，均写入操作人、原因、前后版本、时间和来源链接。权限至少分为：查看、敏感查看、制单、审核/过账、反操作、结账、设置、导出。财务角色按授权拥有写入能力，老板只读/导出，其他角色默认拒绝。

## 华邦数据接入

百胜销售、退货、采购入库以及钉钉报销、付款、工资审批，先经过各自的适配器转换为统一来源单据，再由按账套、业务类型和有效期间配置的规则生成平衡草稿。适配器必须保留原单号、组织、门店/部门、往来单位、金额、税额、附件和来源哈希。

缺少科目、组织、辅助核算、金额、税额或重复来源时，进入异常队列并给出明确原因；不得静默跳过，不得自动审核或自动过账。仅在草稿被财务人员审核和人工过账后，才写入总账、余额和法定报表。

## 质量状态、错误与并发

页面和 API 明确返回 `ready`、`estimated`、`pending_data`、`pending_mapping`、`pending_gap` 或 `stale`。未确认科目映射、账期断档、缺数据或经营估算时，禁止把结果称为正式法定报表。

过账、反过账、结账和反结账在同一数据库事务内执行，并锁定账套期间；草稿使用版本号做乐观并发控制，冲突返回 409。失败不得留下部分分录或部分余额。

## 验收与发布门槛

**Go：**单一 Alembic head；历史导入两次结果相同；历史标记和隔离筛选可见；借贷平衡、状态机、权限、审计与数据适配器测试通过；前端类型检查和构建通过；生产前备份可恢复；生产健康、关键 API、权限和浏览器冒烟验证通过。

**No-Go：**任一金蝶基线或金额核对不一致；历史数据可被当前写入操作改变；自动流程绕过审核/人工过账；迁移出现多个 head；任何来源事实表被意外写入；关键接口 5xx、权限越权或前端构建失败。

## 非目标

- 不写回金蝶，不修改金蝶快照。
- 不复制牧马人非财务模块、配置、部署或业务数据。
- 不把数据缺口、未确认映射或经营估算伪装为正式财务结论。
- 不在未经备份与验证的情况下执行生产迁移。

## V2.1 修订：范围、会计内核与安全上线（本节覆盖前文冲突表述）

### 版本边界

完整财务中心仍是目标，但不再把所有业务域作为同一次开发、迁移和开写的交付物。每一版本只在完成真实会计语义、数据接入、权限、审计和验收后开放；未到版本的页面显示“未启用”，没有创建、编辑或过账入口。

| 版本 | 可交付范围 | 明确不开放 |
| --- | --- | --- |
| V2.0 会计内核 | 会计主体/组织/账簿/政策、期间、科目与辅助维度、币种、凭证工作流、总账/明细账/余额表、历史金蝶迁移、基础资产负债表和利润表、权限审计与附件归档骨架 | 应收应付、银行对账、资产、工资、税务、现金流量表自动分配 |
| V2.1 业务财务 | 费用/付款来源、应收应付、出纳和银行对账、发票、来源单据收件箱与自动草稿 | 资产、工资、税务、合并报表和预算 |
| V2.2 专业子系统 | 固定资产、折旧、工资、税务、现金流量表自动分配、管理会计/预算/合并报表 | 未通过独立验收的后续扩展 |

### 会计主体、账簿与政策模型

V2.0 先确认华邦是法定账、管理账还是两者并行；未取得财务负责人书面确认前，系统不得把报表标为法定报表。实体关系固定为：

```text
法人主体 → 核算组织 → 会计账套 → 会计账簿
                              ├─ 会计政策
                              ├─ 会计年度/期间日历
                              ├─ 科目表及其版本
                              └─ 币种、汇率和报表模板
```

实现实体至少包括 `fin_legal_entity`、`fin_accounting_organization`、`fin_accounting_book`、`fin_accounting_policy`、`fin_fiscal_calendar`、`fin_fiscal_period`、`fin_chart_of_accounts`、`fin_account_version`、`fin_dimension_definition`、`fin_dimension_value`、`fin_account_dimension_rule`、`fin_currency` 与 `fin_exchange_rate`。历史金蝶账套与当前华邦账簿各自绑定一个明确账簿，不共用可变主键或默认数据范围。

科目编码不可修改；已使用科目不可删除。科目版本必须包含父科目、层级、正常余额方向、是否末级、是否允许记账、生效起止日和会计政策。`fin_account_dimension_rule` 必须定义每个可记账科目要求/禁止的客户、供应商、部门、门店、员工、项目等辅助维度组合；自动草稿和人工制单共用同一校验。

所有金额同时支持原币金额、本位币金额、币种、汇率、汇率日期和来源；当前默认本位币为 CNY，但不得把 CNY 写死为唯一币种。已过账凭证的币种、汇率、金额、科目、日期和操作人不可改；汇兑损益和期末外币重估在 V2.2 前保持未启用。

### 凭证、岗位分离与并发

当前账凭证的完整状态为：

```text
draft → submitted → reviewing → approved → posted
               ↘ rejected → draft
draft/submitted/reviewing/approved → cancelled
approved → posting_failed → approved
posted → reversed
```

制单人不能审核自己的凭证；审核人和过账人是否可为同一人必须由会计政策配置，默认分离。已审核未过账的凭证可以撤回至草稿但需记录原因；已过账凭证永远不能编辑或删除，只能生成关联的红字冲销或蓝字更正凭证。凭证号在过账时按账簿、期间连续分配并永久保留，作废号也须保留审计轨迹。

权限拆分为 `finance:voucher:create`、`finance:voucher:submit`、`finance:voucher:review`、`finance:voucher:reject`、`finance:voucher:post`、`finance:voucher:reverse`、`finance:period:close`、`finance:period:reopen`、`finance:history:import`、`finance:audit:view`、`finance:sensitive:view` 和 `finance:export`。`expected_version` 必须落实为带版本条件的单行更新；受服务层之外的批量写入一律禁止。

所有涉及余额的操作遵循锁序：`accounting_book → fiscal_period → voucher → ledger_balance`。必须对序列化失败和死锁执行有限重试，且重试前重新读取版本和状态。

### 数据库级历史隔离

历史隔离不只依赖 `is_historical`。V2.0 使用独立 `fin_history` schema 保存金蝶历史账，当前华邦账只写入 `fin_current` schema；统一查询由只读视图或服务层投影完成。每条历史记录仍保留 `is_historical=true`、`origin_kind=kingdee_history`、来源键、批次与哈希，供审计和前端标记。

`finance_history_importer` 是唯一拥有 `fin_history` 写权限的数据库角色；应用运行角色对该 schema 只有 `SELECT`，不得是表所有者或拥有 `BYPASSRLS`。历史表设置拒绝 `UPDATE`/`DELETE` 的触发器；如部署环境已确认角色分离与策略兼容，再以 `FORCE ROW LEVEL SECURITY` 作为纵深防御。历史表、当前表和子表的外键必须携带账簿/数据域，防止当前凭证引用历史可写对象。

### 结账、电子凭证与安全

重新打开期间不等于允许修改任何已过账凭证。反结账需申请、原因、双人审批、完整审计；旧账只能新增调整或冲销凭证。总账结账前必须校验：未审核/未过账/借贷不平凭证为零、异常来源为零、余额重算通过、损益结转完成；V2.1 起再增加应收、应付、出纳对账差异为零，V2.2 起增加资产子账差异为零。

附件和电子凭证预留 `original_document`、文件哈希、验签/验真状态、结构化载荷、归档状态、归档引用和入账信息文件。首版可只接收与归档，不可将“未验签”表述为已验真。导出必须分为凭证、账簿、报表、审计与电子档案包，记录导出人、条件、字段、时间、水印和下载有效期。

敏感字段采用最小权限、传输加密、静态加密或经确认的替代控制、字段脱敏、短期下载链接、大批量导出告警、附件恶意文件扫描与不可篡改审计链。保留期限、销毁流程、密钥轮换、RPO/RTO 与 PITR 可用性均为生产开写前的待确认项，未确认即 No-Go。

### Expand–Migrate–Contract 与生产切换

历史标记、来源字段和索引不能以一次不可逆的“大迁移”上线。顺序为：预检查并冻结迁移输入 → 新增可空兼容字段/新 schema → 部署可读新旧结构的只读代码 → 分批导入/回填并输出冲突报告 → 并发创建索引和校验约束 → 验证后收紧 `NOT NULL`/权限 → 切换读路径。相同来源键且哈希相同只记录 `already_imported`；来源键相同但哈希不同阻断并生成冲突报告，禁止普通 `ON CONFLICT DO UPDATE` 覆盖历史证据。

生产切换分七阶段：备份与恢复演练、兼容迁移、只读应用发布、历史导入与核对、业务验收、受控开启制单/审核/人工过账、超过回退点后的前向修复。仅在写入冻结窗口内允许恢复迁移前备份；一旦发生真实写入，回退前必须导出新写入并评估重放，超过回退点只能前向修复。旧应用必须先验证与新 schema 兼容；发布锁防止并发发布。

### 验收补充

除原有测试外，V2.0 必须增加：逐账套/年度/期间/科目/辅助维度的迁移核对；同凭证过账、同来源制单、结账与过账、冲销与结账并发测试；百万级分录余额表与大账簿分页性能基线；备份恢复演练；RLS/权限绕过、敏感字段日志泄漏、导出下载权限和历史触发器拦截测试。所有测试结论必须分别标识为本地、试迁移、部署到磁盘、生产只读和生产开写验证。

## 参考与合规边界

本修订使用 PostgreSQL 行级安全与 Alembic 分支文档作为数据库控制和迁移机制的技术依据；电子凭证会计数据标准资料仅用于预留电子凭证能力。它们不构成华邦已完成法定会计软件、电子凭证或监管合规认证的结论；相关法规与会计政策须在 V2.0 阶段由华邦财务负责人和合规顾问确认。
