# 华邦财务中心 V2 设计

## 目标与范围

在华邦 AI 中台内重建一个可独立演进的财务中心，而非把既有拆分页和服务拼装到新菜单。入口固定为“财务利润 → 财务中心”；既有财务首页、利润分析、报销、付款、费用分析、正式账簿与历史财务入口全部保留兼容。

本次交付覆盖账套、科目、辅助核算、凭证、总账、明细账、余额、法定报表、应收应付、出纳对账、资产、发票、工资、税务、自动草稿、期间结账、财务驾驶舱、设置和审计。任何页面必须接入真实查询或受控写入，不能以静态占位冒充可用。

## 核心架构

财务中心采用四层边界：

1. **来源证据层**：金蝶 ODS/DWD 快照保持不可写；百胜、钉钉和华邦业务事实表保持各自所有权。
2. **历史账层**：金蝶记录导入新的 `fin` schema，带不可移除的历史标记和来源链路，用于查询、穿透和与当前账隔离展示。
3. **当前记账层**：当前华邦业务经适配器形成草稿；草稿经审核和人工过账后才影响正式余额与报表。
4. **应用层**：`/api/v1/finance-center` 是新模块唯一后端契约；前端配置集中于 `frontend/src/config/financeCenterModules.ts`，页面不直接依赖旧拆分服务。

新模块可以读取现有经营数据，但不得重写 `dwd_finance_expense`、`dwd_finance_cash`、百胜事实或钉钉事实。所有金额使用十进制精度，禁止浮点入账。

## 历史金蝶数据写入与标记

金蝶数据会写入新的财务模块，但绝不伪装成华邦当期账。每条导入的账套、科目、期间、凭证、分录、余额与来源链接均保存：

- `is_historical=true`；
- `origin_kind=kingdee_history`；
- `source_system=kingdee`、来源账套/数据库、来源主键、导入批次、原始哈希；
- 导入时间、导入执行人、校验结果和可追溯的导入批次。

历史记录默认只读；不能被当前的编辑、审核、人工过账、自动草稿或当前期间结账流程修改。前端在列表、详情、凭证、账簿和报表穿透处显示“历史数据”标记。报表筛选必须明确区分“仅当前华邦账”“仅历史账”“含历史数据”；默认仅当前华邦账，防止无意混算。

导入必须幂等：同一来源键和内容哈希再次运行不会产生重复数据；内容冲突产生阻断性差异报告，而非覆盖原记录。历史数据写入前后分别核对账套、科目、凭证、分录、余额、借贷合计和来源链接；任何差异阻止发布。

## 会计状态与权限

所有当前业务写入统一使用：`draft → reviewed → posted`。冲销生成关联的新凭证；已过账凭证不能直接编辑或删除；已结账期间必须先按权限反结账才能进行允许的反操作。历史导入的记录不参加这条写入状态机。

每次保存、审核、过账、冲销、导入、结账、反结账、规则执行和配置修改，均写入操作人、原因、前后版本、时间和来源链接。权限至少分为：查看、敏感查看、制单、审核/过账、反操作、结账、设置、导出。财务角色按授权拥有写入能力，老板只读/导出，其他角色默认拒绝。

## 华邦数据接入

百胜销售、退货、采购入库以及钉钉报销、付款、工资审批，先经过各自的适配器转换为统一来源单据，再由按账套、业务类型和有效期间配置的规则生成平衡草稿。适配器必须保留原单号、组织、门店/部门、往来单位、金额、税额、附件和来源哈希。

缺少科目、组织、辅助核算、金额、税额或重复来源时，进入异常队列并给出明确原因；不得静默跳过，不得自动审核或自动过账。仅在草稿被财务人员审核和人工过账后，才写入总账、余额和法定报表。

## 质量状态、错误与并发

页面和 API 明确返回 `ready`、`estimated`、`pending_data`、`pending_mapping`、`pending_gap` 或 `stale`。未确认科目映射、账期断档、缺数据或经营估算时，禁止把结果称为正式法定报表。

过账、反过账、结账和反结账在同一数据库事务内执行，并锁定账套期间；草稿使用版本号做乐观并发控制，冲突返回 409。失败不得留下部分分录或部分余额。

## 验收与发布门槛

**Go：**单一 Alembic head；历史导入两次结果相同；历史标记和隔离筛选可见；借贷平衡、状态机、权限、审计与数据适配器测试通过；前端类型检查和构建通过；生产前备份可恢复；生产健康、关键 API、权限和浏览器冒烟验证通过。

**No-Go：**任一金蝶基线或金额核对不一致；历史数据可被当前写入操作改变；自动流程绕过审核/人工过账；迁移出现多个 head；任何来源事实表被意外写入；关键接口 5xx、权限越权或前端构建失败。

## 非目标

- 不写回金蝶，不修改金蝶快照。
- 不复制牧马人非财务模块、配置、部署或业务数据。
- 不把数据缺口、未确认映射或经营估算伪装为正式财务结论。
- 不在未经备份与验证的情况下执行生产迁移。
