# V2.0 期初余额核对与锁定记录

> 状态：实施中的操作契约。本文描述已落盘的本地接口与核对顺序，不代表任何生产账簿已启用或允许写入。

## 目的与边界

- 期初批次只写入 `fin_current`，金蝶历史快照、ODS/DWD 和已发布 `fin_history` 均不被修改。
- 批次有 `provisional`（预演）与 `final`（最终）两类；预演仅供只读验收和核对，不能改变账簿启用日。
- 当前账写入的前置仍是：最终批次已锁定、历史覆盖连续或断档获批且正式报表受阻断、以及独立的 `draft_enabled`、`review_enabled`、`post_enabled` Gate。锁定本身不打开任何写入 Gate。

## 操作顺序

1. 在旧系统仍为唯一正式账时，创建预演批次，逐科目、维度集、币种录入有来源依据的余额。
2. 以余额表或逐凭证结果核对：借贷合计相等、每行有 `source_system`、历史截止日早于 V2 启用日；缺来源的金额进入异常，不能填零掩盖。
3. 调用验证命令。验证只把批次从 `draft` 变成 `validated`，不改变账簿启用边界。
4. 最终切换窗口内冻结旧系统，导入并核对最终增量，废弃预演批次后创建最终批次。
5. 仅在 `cutover_enabled` 已按全局/环境/账簿/角色范围明确启用时，锁定已验证的最终批次；锁定写入审批和操作事件，并更新账簿历史截止日、启用日及正式报表阻断标记。
6. 重新读取写入 readiness。只有最终锁定期初和相应功能 Gate 同时满足时，才可以按既定顺序启用制单、审核、人工过账。

## 核对字段

| 维度 | 必须核对 | 不通过时处理 |
| --- | --- | --- |
| 覆盖日期 | 历史截止日、启用日、是否连续 | 不连续必须有获批 `coverage_gap`；正式报表维持阻断 |
| 余额 | 借方合计等于贷方合计且金额大于零 | 保持草稿，修正来源/明细后重新验证 |
| 行级键 | 科目版本、维度集、币种唯一 | 合并或拆分来源明细，禁止覆盖既有锁定行 |
| 来源 | 每行来源系统和可追溯引用 | 进入异常，不以人工默认零替代 |
| 并发 | `expected_version` 与当前版本一致 | 返回 409，刷新批次后重新确认 |

## 接口与审计

| 动作 | 路径 | 权限 | 不变量 |
| --- | --- | --- | --- |
| 列出批次 | `GET /api/v1/finance-center/v2/books/{book_id}/opening-balances` | `finance:center:view` | 只读 |
| 创建草稿 | `POST /api/v1/finance-center/v2/books/{book_id}/opening-balances` | `finance:center:operate` | 不改变启用日或写入 Gate |
| 验证草稿 | `POST .../{batch_id}/validate` | `finance:center:operate` | 借贷平衡、来源字段、乐观并发 |
| 锁定最终期初 | `POST .../{batch_id}/lock` | `finance:center:operate` + `cutover_enabled` | 仅 `validated` 可锁定，操作事件和命令幂等必写 |

同一 `command_id` 与相同请求体应返回原结果；相同键但请求体不同必须阻断。锁定后的批次和明细由数据库触发器保护，不能直接更新。

## 失败与恢复

- 验证/锁定失败：事务回滚，批次保持原状态；修正后使用新命令键重试。
- 版本冲突：不覆盖他人提交，刷新后重新核对。
- 未通过切换 Gate：保持旧系统唯一正式写路径，V2 不开启制单、审核、过账。
- 第一张 V2 正式凭证过账后：不再直接修改期初；通过开放期间的调整凭证前向修复。
