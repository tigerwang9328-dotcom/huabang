# 华邦财务中心 V2 总体路线图

## 单一执行来源

本路线图和同目录的 `design.md`、`implementation-plan.md` 是唯一有效的后续依据。`archive/` 中的文件均已归档，禁止执行。

## 版本范围

| 版本 | 目标 | 可以开写的条件 | 未启用范围 |
| --- | --- | --- | --- |
| V2.0 会计内核 | 账簿、期间、科目/维度、币种、凭证、总账、基础报表、历史金蝶、审计 | 历史与当前账隔离、期初余额锁定、只读发布和开写 gate 全部通过 | 应收应付、银行对账、资产、工资、税务、现金流量表自动分配，以及附件上传/对象存储/恶意文件扫描 |
| V2.1 业务财务 | 费用付款来源、发票、应收、应付、出纳和银行对账 | 每个子账与总账对账为零，独立生产验收通过 | 资产、工资、税务、预算、合并报表 |
| V2.2 专业域 | 资产、折旧、工资、税务、现金流量表自动分配、管理会计/预算/合并报表 | 数据来源、会计政策、对账、权限和回滚各自通过 | 未独立验收的后续扩展 |

页面或 API 不等于完成；未到版本的域必须展示“未启用”，不得提供写入口或模拟数据。

V2.0 的来源接入仅限收件箱、规则版本、异常队列和对生产数据的只读预览。百胜或钉钉正式适配、自动草稿和来源同步属于 V2.1 的逐来源试点，必须按 [来源试点计划](../v2.1/source-pilot-plan.md) 先确认子账边界、关联键、补建历史与回滚方式。

## 数据域和事实源

```text
fin_history  : 金蝶历史凭证分录是历史会计事实源；历史余额仅为核对快照/性能读模型
fin_current  : 当前已过账凭证分录是当前会计事实源；ledger_balance 是可重建读模型
统一查询视图: 按账簿和明确数据范围投影，不能用 UNION ALL 直接相加重叠期间
```

历史范围和当前范围由已批准的 `history_coverage_end_date` 与 `current_book_go_live_date` 决定。默认当前账起始日必须等于历史覆盖截止日后一天；不连续时必须存在已批准的 `coverage_gap` 且阻断跨区间正式报表。任何重叠期间阻断“含历史数据”查询，直至财务负责人明确选择优先账簿并形成审计记录。

## 旧入口兼容矩阵

| 旧入口类型 | V2 只读验收 | 切换冻结 | V2 开写后 |
| --- | --- | --- | --- |
| 旧查询 API | 保持原行为 | 只读 | 代理至 V2 只读查询或返回废弃提示 |
| 旧制单 API | 保持唯一正式制单入口 | 禁止 | 关闭或转接 V2 制单 |
| 旧审核/过账 API | 保持唯一正式审核/过账入口 | 禁止 | 永久关闭/410 |
| 旧财务页面 | 保持原工作流 | 冻结提示 | 跳转新页面或明确只读 |
| 旧财务表 | 继续原正式账写入 | 停止写入并最终核对 | 不得再作为正式账写入目标，留存至保留期结束 |

V2 只读验收阶段旧系统是唯一正式写账系统；切换冻结阶段两侧写入均关闭；V2 开写后只有 V2 `post` 服务可写当前正式总账。禁止双写；旧写路径关闭时间、适配状态和最终下线日期必须登记在发布基线中。

## 发布和恢复边界

生产过程依次为：备份/恢复演练、兼容迁移、只读应用发布、历史暂存导入和发布、预演期初建账、财务验收、凭证工作台与权限验收、冻结旧系统、导入最终增量并批准最终期初、开启 V2 制单、开启 V2 审核、开启 V2 人工过账、Contract 清理。仅写入冻结窗口内可恢复旧备份；发生真实写入后必须先导出并演练重放，超过应用发布回退点的普通故障只允许前向修复。

数据库物理损坏、存储故障、大范围误删或安全事件属于灾难恢复：可按已验证 PITR/备份恢复流程恢复，并对 RPO 范围内缺失交易进行重放、补录和财务核对；这不等同于普通发布版本回退。

V2.0 开写前必须确认 RPO、RTO、备份恢复、PITR 能力、发布锁、数据库角色和历史导入角色；任何一项未验证为 No-Go。
