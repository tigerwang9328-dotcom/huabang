# Finance V2.0 期边切换运行手册

> 状态：预案，禁止在 V2 只读验收阶段执行。默认仅允许会计期间边界切换；月中增量方案须另行实现、测试并在恢复副本演练。

## 已核实边界

- V2 写入口为 `/api/v1/finance-center/v2`，并受全局、环境、账簿、来源和角色 Gate 约束。
- 旧正式账写入口仍为 `/api/v1/finance-center`：`POST /kingdee/import`、`/periods/open`、`/vouchers`、`/vouchers/{id}/post`、`/vouchers/{id}/reverse`、`/vouchers/{id}/revise`。只读阶段不得关闭或改写它们。
- 历史金蝶事实仅由 `fin_history` 发布后经 `fin_read` 可读；V2 当前账事实仅写入 `fin_current`。

## 必须全部为 Go 的输入

| Gate | 可接受证据 | 失败处置 |
| --- | --- | --- |
| 异机恢复 | 在隔离目标恢复并完成 339/4,596 历史核对，实测 RPO≤24h、RTO≤4h | 保持旧系统唯一写入口 |
| 通知闭环 | 告警接收人、送达、确认和关闭演练记录 | 不开启任何 V2 写 Gate |
| 当前账事实 | 账簿、科目、维度、币种、下一期间、最终期初逐余额核对并锁定 | 不开启 V2 草稿 |
| 冻结窗口 | 明确负责人、开始/结束时间、旧系统写入清单和回退负责人 | 不冻结旧入口 |
| 试点范围 | 财务角色/超级管理员、账簿及首张人工凭证范围明确 | 不开启审核或过账 |

## 执行顺序

1. 记录生产提交、Alembic 单一 head、备份校验值、`verify_finance_center_v2.py` 输出和全部 Gate 状态。
2. 在批准窗口内冻结上述旧写入口；验证每个写请求被拒绝且旧查询仍可读。此时 V2 Gate 仍全部关闭。
3. 旧期间结账后提取最终余额；废弃预演期初，创建、验证、批准并锁定 V2 下一期间最终期初。逐科目/维度/币种核对借贷平衡。
4. 仅对获批账簿和试点角色开启 `draft_enabled`；创建一张人工凭证草稿并完成幂等、审计、并发冲突和不可见性核验。
5. 永久关闭或 410/转接旧制单、审核、过账入口，并记录调用量归零证据；不允许双写。
6. 完成日对账后，依次开启 `review_enabled`、`post_enabled`；每一步均以一张人工凭证试点、独立审核、人工过账和余额重建核对为 Gate。

## 停止与恢复

- 最终期初未锁定、逐余额差异非零、旧写入口无法确认冻结、告警未闭环或任何 V2 Gate 误开：立即停止，不创建 V2 正式凭证。
- 第一张 V2 凭证过账前：可恢复旧入口并废弃未锁定期初；必须记录原因和审计证据。
- 第一张 V2 凭证过账后：普通发布故障仅允许前向修复；数据库灾难才使用已验证恢复流程并补录 RPO 范围内交易。
