# 华邦财务中心 V2.0 实施计划

> **For implementation:** 此文档是唯一可执行计划。不得读取或执行同目录 `archive/` 中财务中心文档的 Task、checkbox、迁移名或发布步骤。

**Goal:** 交付可核对、可审计且可受控开写的华邦会计内核；金蝶历史数据通过隔离的暂存—校验—发布流程只读呈现，华邦来源单据在 V2.0 仅做只读预览和异常分析，不生成生产草稿。

**Architecture:** `fin_history` 保存已发布的金蝶历史账，`fin_current` 保存当前账；凭证分录是会计事实源，`ledger_balance` 是可重建读模型。唯一正式写入口是 V2 凭证服务，旧入口不存在并行过账或双写。

**Tech Stack:** FastAPI、SQLAlchemy、Alembic、PostgreSQL、pytest、Vue 3、TypeScript、Element Plus、Vite、Playwright、Linux Shell 生产入口与 Windows PowerShell SSH 编排入口。

## 全局不变量

- 金蝶 ODS/DWD、百胜、钉钉和既有费用/现金事实表不被 V2 写入。
- 生产前先核实当日 Alembic heads，不能沿用归档文档中的 revision ID。
- 历史数据不允许 `ON CONFLICT DO UPDATE` 覆盖；仅已发布导入批次可见。
- 当前账只允许草稿、提交、审核、批准、人工过账、冲销；自动化永不审核或过账。
- 真实写入发生后的异常只允许前向修复；恢复旧备份只限写入冻结窗口。

| `voucher_number_counter`、`voucher_number_reservation`、`command_execution`、`posting_attempt`、`operation_event` | Phase 3 | `add finance v2 voucher workflow` revision |

| `opening_balance_batch`、`opening_balance_line`、`opening_balance_dimension`、`opening_balance_reconciliation_item`、`opening_balance_approval`、`coverage_gap` | Phase 4.5 | `add finance opening balance boundary` revision |
| 附件/归档元数据、报表模板/映射/快照 | Phase 5 | `add finance reports and archive metadata` revision |
