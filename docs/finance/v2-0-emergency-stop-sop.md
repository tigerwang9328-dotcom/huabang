# 华邦财务中心 V2.0 紧急停止 SOP

> 目标：在不影响已发布历史查询、已过账凭证只读审计或旧财务系统既有写路径的前提下，立即拒绝 Finance V2 当前账的草稿、审核、人工过账、结账和来源同步命令。

## 触发条件

- 过账失败、借贷不平阻断、历史冲突、结账失败、余额差异、锁等待/死锁或 API 5xx 达到可用阈值；
- 发现权限越权、审计缺失、重复写入或任何无法解释的当前账变化；
- 发布、迁移或最终切换演练未达到既定 Gate。

## 处置顺序

1. 值班财务负责人记录时间、现象、账簿/期间范围和处置负责人；不要在常规日志中复制凭证或个人数据。
2. 由受控数据库管理员在 `fin_current.feature_gate` 写入或更新 `global/*/emergency_stop=true`，写入人、理由、批准人和生效时间必须完整。此操作只允许经受控生产变更窗口执行。
3. 用已有财务角色调用 V2 写入就绪接口，确认草稿、审核、过账、结账均被拒绝；历史查询和已过账凭证只读审计仍可访问。
4. 暂停任何 V2 当前账试点操作，保留 `posting_attempt`、`operation_event`、Gate 记录、监控响应和服务日志。
5. 修复必须前向进行；真实写入后不得通过删除凭证、删除 Gate 记录或覆盖历史数据“恢复正常”。数据库灾难才进入已验证 PITR 流程。

## 解除条件

- 根因、影响范围与余额核对结果已记录；
- 必要的前向修复、冲销或调整凭证方案已经审核；
- 相关指标连续稳定，且财务负责人确认可以恢复试点；
- 解除 emergency stop 后，仍按顺序单独批准 `draft_enabled` → `review_enabled` → `post_enabled`；不得一次性跳过审核或人工过账阶段。

## 禁止事项

- 不得通过关闭鉴权、中台权限扩大、应用账户提权或直接删除审计记录绕过停止开关。
- 不得把 V2 emergency stop 解释为旧系统停机；只读验收阶段旧系统仍是唯一正式写入路径。
- 不得在没有异机恢复证据、最终期初和旧入口冻结证据时解除正式开写 No-Go。
